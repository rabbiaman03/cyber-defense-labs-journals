# Learning Journal 0 — Review of Risk Management

Review of Basic Risk Management

1. Risk management is way to secure and analysis the risk that can effect businesses. In more words, it is a way of saving company's and customer's data by implementing different tasks. The tasks can be conducted by ranking them with potential risks and putting efforts to protect them by software platforms or third party administrator. 
2. There are several steps to conduct risk management. First and foremost step would be identifying assets and processes. This can be done by conducting assets including software, hardware, stored data to make data and documents about risk. By looking at the data and all the information, company should identify their risk. It can be different risks based on the  company's strategy. They will look for any non-compliance regulation, network security vulnerabilities, employee mistakes or any machine failure. That's how they can identify their risk in the system. Then the third step will be ranked them according to their risk volume and evaluate them. After ranking and evaluating the risks, they have to implement strategies to mitigate the problem. Strategies can be physical or software dependent. The last stage would be monitoring the software and further risks.
3.  The four risk mitigation strategies are- 
a. Risk Avoidance: The company can eliminate risks by cutting off unnecessary data from database or system, including unnecessary employee's data such as age or anything that are not required to run the business. 

b. Risk Mitigation: When avoiding data can be expensive or unavoidable, company's can take steps to mitigate the risks. Many security measures can be taken including physical, technical and organizational controls. CCTV, monitor sensor or security guard can be good assets for physical control. For logical controls, the  best tool would be firewalls to protect the system from unwanted server or network. Antivirus and other security platforms or software can be a good asset too. 

c.  Transfer of Risk: Transferring risk means saving data to different location as a backup data, such as cloud or other services. Transferring risk can also include transferring risks to a third party. They will monitor the system data and possible risks. 

d. Risk Acceptance: Lastly, businesses can accept the risk as their business strategy. When mitigating is too costly than the possible loss of data breaching, the company can accept the risks. 

Defining IT security terms by following:
1. Risk: The potential loss or damages after data breaching or when threats exploit vulnerabilities.
2. Threat: Anything that can impact company's assets or data. It can be malware or any other files or software. 
3. Threat actor: The person or group of people behind the data loss or hacking. It can be a hacker or insider employee. 
4. Attack surface: It is all the area where attackers can spread vulnerability and can have the access of the data.
5. Exploit: It is a method of how an attacker can take advantages of possible risks(vulnerability) of the system. They can use tools for this 
6. control: A safeguard that can reduce risks. It can be technical, physical. For example, cryptography, firewall, security guard etc.


8 Rules Review

According to Kevin Day's Inside the Security, the 8 rules of security are-

1. Rule of Least Privilege: The least privilege includes giving minimal access to the users. Grant only access to operate the system can lead to have safe work environment. It is also a way of having the least loss from data breaches. For example, users should not have all the file access and monitoring them without a system administrator. The administrator can have all the root permission for file transfer and file editing. 

2. Creating a chokepoint: Creating chokepoint means defining perimeter where external connections can be restricted. It is the way where companies applied one or more chokepoints to block users from installing modems, enabling access services, or making any other external connection without going through a designated perimeter chokepoint. It also helps organization to block users from illegal file access. It can be done by implementing VPN in organization. 

3. Layering Defenses: Layering the defenses mean protecting data from different layers. Data that can be corrupted by hackers routes by a company router or other network tools. By providing multiple defense layer, data can be transferred safely within the network. It will strengthen the security of a company and can mitigate the possible loss of a company. Layering defenses can include dropping unwanted data using firewall, blocking ip addresses from different network. 

4. Rule of Trust: The perimeter of trust is the most famous form of network safety. It is operated by a different organization or third party who control and manage network security of the system. It builds on  trust, where one company give all access to another to provide security and safety of their data. Other party implement all the steps to provide security and make a safe environment in the system. 

5. Rule of the Three-Fold Process: Though using firewall and other tools can lead secure network and administrative files, it needs to be updated and monitored. Since the data and information is connected to outside world, hackers can hack data and eventually it can lead to major loss to company. Therefore, it is very important to make all the logs of suspicious activity and monitor them by time to time. 

6. The Concept of Thinking in Zones: The concept of thinking in zones comes from  how access is taking place between subjects and objects. It means each communication from end to end should go such perimeter where data is being secured and proceed with certain level of secure medium.  DMZs and relayed services are common security measures found at the perimeter.

7. The Concept of Working in Stillness: As our device is connected to a big network, there is a big chance to have vast number of traffic is passing in the network. If we use tools like firewall and log files, it will be impossible to find the real hacker. So the concept of working in stillness comes to play. For example, if a company analyze all the data and work for each of them, there will be less chance to loss data from the system and eventually it will secure the network. 

8. Internal Defenses: The network is connected both internally and externally, and so internal defenses should come to play roles. Company's should enforce more security measures to protect it by filtering firewall rules and giving less permission and administration power to users. In a internal network data can be stolen easily if there is no limitation of access to those file. So log files can play a vital role in this case.

2. When we are likely to take any services, we give our valuable information which can be used  to identify ourselves to hackers. Information such as date of birth, name, Social Security number, address etc. Also in some medical system we give our medical history and they  store our prescription records.  3. 5 common IT security compliance frameworks are:
 
HIPAA (Health Insurance Portability and Accountability Act): As a healthcare personal, you have to store personal information about patient's name, address, insurance number. So this act ensures the protection of the data.

California Consumer Privacy Act(CCPA): It sets rules and regulations for California's Customer data security in terms of bank transaction and personal details.

CIS Critical Controls

1. Inventory and Control of Enterprise Assets: It is to know and monitoring all the activities and devices within the enterprise. It can be physical device or devices which are connected to cloud or virtually. It will help to remove unauthorized assets. 
2. Inventory and Control of Software Assets: It tracks installed software and makes sure only authorized software is installed. 
3. Data Protection: It will protect data by encrypted data, identify and classify data. That's how it secures data lifecycle whether at rest or in transit.
4. Secure Configuration of Enterprise Assets and Software: It hardens devices and apps with secure baseline configurations, by using configuration management, benchmarks.
5. Account Management: It governs all user accounts, software, and services. It also secures credentials for users and administrator accounts. 
6. Access Control Management: Giving least privileges to users and administrator to take services. It can add, remove and manage the access.
7. Continuous Vulnerability Management: Spotting gaps in vulnerability and preparing for future threats. Monitoring and scanning the system can find vulnerability in the system.
8. Audit Log Management: Collect, monitor, retain logs from critical assets. Enable alerting, centralized logging with analysis tools can help.
9. Email and Web Browser Protections: To protect direct engagement with users including emails or any other web vectors, it should be protected and supervised. 
10. Malware Defenses: Prevent malware execution by detecting malicious code or scripts on enterprise assets. 
11. Data Recovery: Storing data to a different trusted state and maintain it. Data can be recovered from the source to enterprise.
12. Network Infrastructure Management: Secure network devices such as, routers, switches, firewalls with proper controls, segmentation, access control. 
13.  Network Monitoring and Defense: Monitoring and securing security threats in a network. It can be processed with tools like SIEM.
14. Security Awareness and Skills Training: Making security awareness among workforce will reduce cybersecurity risks to the enterprises. 
15. Service Provider Management: Ensuring safe data from the providers who hold sensitive data. They can be responsible for an enterprise's critical data loss.
16. Application Software Security: Managing the security of in-house developed, hosted, or acquired software to prevent and detect the weakness of a network before they can impact the enterprise. 
17. Incident Response Management: Build and maintain roles, playbooks, training, communication plans, post-incident reviews to response an attack. 
18. Penetration Testing: Simulate real-world attacks to identify weaknesses in the system. Conduct external/internal pen tests regularly and act on findings any weaknesses.
